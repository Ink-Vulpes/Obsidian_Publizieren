MCP Setup

KI-Zugriff auf Ihren Vault via Model Context Protocol

Was ist MCP?

Das Model Context Protocol (MCP) ist ein offener Standard, der von Anthropic entwickelt und am 25. November 2024 als Open-Source-Projekt veröffentlicht wurde. Es standardisiert, wie KI-Assistenten (große Sprachmodelle) auf externe Daten und Tools zugreifen.

Vor MCP musste für jede Kombination aus KI-Modell und Datenquelle eine eigene Schnittstelle gebaut werden – das sogenannte M×N-Integrationsproblem. MCP löst dies mit einer universellen, modellunabhängigen Schnittstelle auf Basis von JSON-RPC 2.0:

HostDein KI-Assistent
(Claude, ChatGPT …)
→
MCP ClientEingebaut im Host
→
MCP ServerDieser Vault
(/mcp Endpunkt)

Inzwischen unterstützen alle großen KI-Anbieter MCP – darunter OpenAI, Google DeepMind und Microsoft. MCP-Server können lokal (stdio) oder remote (HTTP) betrieben werden. Dieser Vault läuft als HTTP-Server und ist damit von jedem MCP-kompatiblen Client erreichbar.

Schritt 1 – API-Token generieren

Generieren Sie einen langlebigen Token (1 Jahr Laufzeit), den Sie in Ihrer Agent-Konfiguration hinterlegen. Der Token wird mit Ihren Rechten ausgestellt – Sie sehen nur Notizen, auf die Ihr Account Zugriff hat.

Dieser Token wird nur einmal angezeigt. Kopieren Sie ihn jetzt – er kann später nicht mehr eingesehen werden.

Schritt 2 – Agent konfigurieren

Wählen Sie Ihren KI-Assistenten und folgen Sie der jeweiligen Anleitung. Der in Schritt 1 generierte Token wird in allen Fällen benötigt.

C Claude Desktop Empfohlen

Öffnen Sie Ihre Claude-Desktop-Konfigurationsdatei:

  • macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
  • Windows: %APPDATA%\Claude\claude_desktop_config.json

Fügen Sie folgenden Eintrag in den mcpServers-Block ein:

{
  "mcpServers": {
    "obsidian-vault": {
      "url": "{{ base_url }}/mcp",
      "headers": {
        "Authorization": "Bearer IHR_TOKEN"
      }
    }
  }
}

Starten Sie Claude Desktop neu. Der Vault erscheint danach als verfügbares Tool.

G OpenAI ChatGPT Desktop

ChatGPT Desktop (ab Version 1.2025.x) unterstützt MCP-Server. Öffnen Sie die Konfigurationsdatei:

  • macOS: ~/Library/Application Support/com.openai.chat/mcp.json
  • Windows: %APPDATA%\OpenAI\ChatGPT\mcp.json

Erstellen oder ergänzen Sie die Datei mit:

{
  "mcpServers": {
    "obsidian-vault": {
      "url": "{{ base_url }}/mcp",
      "headers": {
        "Authorization": "Bearer IHR_TOKEN"
      }
    }
  }
}

Starten Sie ChatGPT neu. Der Vault steht dann als Tool in Gesprächen zur Verfügung.

M Microsoft 365 Copilot

Für Microsoft 365 Copilot wird ein eigener Copilot Studio Connector benötigt:

  1. Öffnen Sie Copilot Studio und wählen Sie Ihren Copilot.
  2. Navigieren Sie zu Einstellungen → Aktionen → Connector hinzufügen.
  3. Wählen Sie Benutzerdefinierter Connector und tragen Sie ein:
    • Endpunkt: {{ base_url }}/mcp
    • Authentifizierung: API-Key / Bearer Token
    • Header: Authorization: Bearer IHR_TOKEN
  4. Speichern und Copilot neu deployen.

Hinweis: Copilot Studio ist ein kostenpflichtiges Microsoft-Produkt. Diese Option erfordert Administratorrechte im M365-Tenant.

◆ Google Gemini CLI

Das Gemini CLI (Open Source, lokal installierbar) unterstützt MCP-Server ab Version 0.1.x. Öffnen Sie die Konfigurationsdatei:

  • macOS/Linux: ~/.gemini/settings.json
  • Windows: %USERPROFILE%\.gemini\settings.json
{
  "mcpServers": {
    "obsidian-vault": {
      "httpUrl": "{{ base_url }}/mcp",
      "headers": {
        "Authorization": "Bearer IHR_TOKEN"
      }
    }
  }
}

Starten Sie das Terminal und führen Sie gemini aus – der Vault erscheint danach als Tool.

L LM Studio Lokal

LM Studio unterstützt MCP-Server ab Version 0.3.x über die Agenten-Funktion:

  1. Öffnen Sie LM Studio und wechseln Sie zum Tab Agent.
  2. Klicken Sie auf MCP Servers → Add Server.
  3. Wählen Sie den Typ HTTP (Streamable) und tragen Sie ein:
    • URL: {{ base_url }}/mcp
    • Header: Authorization → Bearer IHR_TOKEN
  4. Verbindung testen und speichern.

LM Studio läuft vollständig lokal – Ihre Anfragen verlassen das Gerät nicht (außer für den Datenzugriff auf den Vault-Server).

O Ollama (mit Open WebUI) Lokal

Ollama selbst ist nur ein Modell-Runner ohne MCP-Client. Sie benötigen ein Frontend, das MCP unterstützt – zum Beispiel Open WebUI:

  1. Installieren Sie Open WebUI (z. B. via Docker oder pip install open-webui).
  2. Navigieren Sie in Open WebUI zu Einstellungen → Tools → MCP Servers.
  3. Legen Sie einen neuen Server an:
    • URL: {{ base_url }}/mcp
    • Header: Authorization: Bearer IHR_TOKEN
  4. Aktivieren Sie den Vault im Chat-Fenster als Tool.

Alternativ: mcpx als CLI-Proxy (npx @modelcontextprotocol/inspector) oder Msty als Desktop-App mit MCP-Unterstützung.

? Anderer Agent (allgemein)

Jeder MCP-kompatible Client kann diesen Vault einbinden. Der Server verwendet den HTTP-Transport (Streamable HTTP / SSE) – kein stdio. Sie benötigen folgende Angaben:

Endpunkt{{ base_url }}/mcp
TransportHTTP POST (JSON-RPC 2.0)
AuthAuthorization: Bearer IHR_TOKEN (Header)
ProtokollMCP 2024-11-05

Zum Testen der Verbindung können Sie auch den MCP Inspector verwenden:

npx @modelcontextprotocol/inspector \
  --url {{ base_url }}/mcp \
  --header "Authorization: Bearer IHR_TOKEN"

Schritt 3 – Verfügbare Tools

Nach der Verbindung stehen Ihnen folgende Tools zur Verfügung:

search_notes

Volltextsuche über Titel und Inhalt aller Notizen. Gibt bis zu 20 Treffer mit Auszug zurück.

search_notes(query: "Photosynthese")
read_note

Liest den vollständigen Markdown-Inhalt einer Notiz anhand ihres Slugs.

read_note(slug: "Biologie/Mitose")
list_notes

Listet alle sichtbaren Notizen mit Titel, Slug und Tags (Standard: max. 100).

list_notes(limit: 50)

Gruppenrechte werden automatisch angewendet – der Agent sieht nur Notizen, auf die Ihr Account Zugriff hat.

Beispiel-Prompts

Nützliche Fragen für die Arbeit mit fremden Inhalten – wenn Sie den Vault nicht selbst erstellt haben:

  • „Welche Themen oder Fachbereiche sind in diesem Vault vorhanden? Bitte geben Sie mir einen Überblick."
  • „Erklären Sie mir das Konzept [Begriff] anhand der Notizen in diesem Vault."
  • „Gibt es in den Notizen Verbindungen zwischen [Thema A] und [Thema B]?"
  • „Fassen Sie alle Notizen mit dem Tag #[Tag] in einer strukturierten Übersicht zusammen."
  • „Welche Quellen, Literatur oder weiterführenden Hinweise werden in den Notizen über [Thema] erwähnt?"
  • „Erstellen Sie eine Lernzusammenfassung zu [Thema] aus den vorhandenen Notizen."
  • „Wo gibt es in den Notizen inhaltliche Widersprüche oder offene Fragen zu [Thema]?"
